Table2FBD — использование программы

Распакуйте архив и запустите Table2FBD.exe. Установка Excel не требуется.
Обе версии сами читают и записывают .xlsx. Подключение к ПЛК не выполняется.
Версия C++ работает в 32- и 64-разрядных Windows 10/11. Python, Qt и BPL
не требуются: библиотеки C++Builder подключены статически.
Версия Python работает в Windows 10/11 x64. Установка Python не требуется,
но папка _internal из архива должна оставаться рядом с программой.
Table2FBD-cli.exe — отдельная консольная программа в каждой поставке.

1. Нажмите «Новая» или «Открыть…». Пример: «Файл → Открыть пример».
2. На вкладке «Поля» задайте названия, типы и имена входа/выходов.
3. На вкладке «Записи» добавьте строки и заполните значения.
4. При необходимости сохраните таблицу в Excel кнопкой «Сохранить…».
5. Укажите имя макроса. Отметьте FBD и/или ST. По умолчанию включены оба.
6. Для каждого формата отдельно выберите «Всё в один» или «По группам».
   Шаг по ID также задаётся отдельно для FBD и ST.
7. Создайте макросы и импортируйте .tple / .fbst в OwenLogic.
8. В режиме групп используйте сводный макрос без суффикса диапазона.

Например, FBD может содержать сводный макрос и группы с шагом 10 по ID,
а ST — один макрос CASE на всю таблицу. Допустима обратная настройка.
Генерация использует текущие данные окна, включая несохранённые изменения.
Выбор листа отображается только при наличии нескольких листов в книге.

РЕДАКТИРОВАНИЕ
Изменяйте ячейки на вкладках «Поля» и «Записи». Тип выбирается из списка.
Поля можно добавлять, удалять и переставлять. Значения перемещаются вместе
с соответствующими полями. При смене типа значения проверяются заново.
Строки можно добавлять, копировать и удалять. Копия получает свободный ID.
Ctrl+C / Ctrl+V — обмен диапазоном ячеек; Ctrl+Z / Ctrl+Y — отмена и повтор.
Звёздочка в заголовке означает несохранённые изменения таблицы.
Меню «Файл → Перечитать файл» заново загружает книгу с диска.

При сохранении создаётся книга .xlsx с одним листом «Данные».
Оформление и другие листы исходной книги не переносятся. Для первоначально
открытой книги требуется другое имя файла. Созданную программой книгу
можно затем перезаписывать. Изменения полей и записей можно отменять.
Template.xlsx содержит вымышленные режимы вентилятора.

ФОРМАТ ТАБЛИЦЫ
Строка 1: название поля — пояснение для пользователя.
Строка 2: тип — ID, Комментарий (или COMMENT), REAL, UDINT, BOOL.
Строка 3: имя входа или выхода макроса.
Строки 4 и далее: одна запись в каждой строке.

Обязательны ровно один ID и хотя бы один REAL, UDINT или BOOL.
ID создаёт единственный вход. REAL, UDINT и BOOL создают выходы.
Для комментария имя выхода оставьте пустым. Valid создаётся автоматически.
ID и UDINT: целые числа от 0 до 4294967295.
REAL: конечное число, представимое 32-разрядным типом REAL.
BOOL: 0/1, TRUE/FALSE; в редакторе также ИСТИНА/ЛОЖЬ.
В редакторе десятичный разделитель — точка или запятая.
В Excel используйте числовые ячейки; разделитель зависит от настроек Excel.

Имена: буквы, цифры и знак подчёркивания, не более 64 знаков.
Для ST первый знак должен быть буквой; ключевые слова ST запрещены.
Имена не должны повторяться без учёта регистра. Имя ST-макроса не должно
совпадать с именем его порта. Valid зарезервировано для признака записи.
Формулы, ошибки Excel, повторные ID, пустые числовые ячейки и значения вне
диапазона типа отклоняются. Полностью пустые строки пропускаются.
Пропуски ID допустимы. Формулы предварительно замените их значениями.
Поддерживается .xlsx. Старый формат .xls не поддерживается.

РЕЗУЛЬТАТЫ И РЕЖИМЫ
FBD: файл .tple. ST: файл .fbst с исходным кодом CASE.
При выборе обоих форматов создаются два файла с одинаковой основой имени.
Расширение выходного пути не выбирает язык: используйте флажки или ключи.
Например, --output Result.tple создаёт Result.tple и Result.fbst.

«Всё в один»: один макрос с полной таблицей.
«По группам»: сводный макрос и вложенные группы в одном архиве выбранного
формата. На схему помещается сводный макрос; он сам выбирает нужную группу.
При имени FanModes: FanModes — сводный; FanModes_00_09 и т. д. — группы.
В FBD сводный макрос выбирает выходы группы с Valid=TRUE.
В ST сводный CASE выбирает диапазон и вызывает соответствующий ST-макрос.
Макросы FBD содержат только FBD; макросы ST содержат только ST.

Шаг 10: диапазоны 0–9, 10–19 и далее; шаг 20: 0–19, 20–39 и далее.
Группы определяются по ID, а не по положению строки. Пустые группы отсутствуют.
Допустимый шаг: от 1 до 4294967296. Настройки FBD и ST независимы.
Если ID найден: Valid=TRUE, выходы равны параметрам записи.
Если ID отсутствует: Valid=FALSE, все выходы равны нулю / FALSE.
Значения предыдущего найденного ID не сохраняются.
FBD сравнивает ID как UDINT, без преобразования в REAL.
ST присваивает значения выбранной записи; при неизвестном ID выходы сбрасываются в ELSE.

При одинаковом имени идентификаторы макросов воспроизводятся. У FBD и ST
разные идентификаторы: две версии одной таблицы не заменяют друг друга.
Для независимых таблиц используйте разные имена макросов.
После изменения портов проверьте подключения в проекте OwenLogic.
Ручные правки готового макроса не переносятся обратно в таблицу.

КОНСОЛЬНЫЙ ЗАПУСК
Table2FBD-cli.exe "Таблицы\Режимы.xlsx"
Создаёт Режимы.tple и Режимы.fbst рядом с входной книгой.

Только ST, один макрос на всю таблицу:
Table2FBD-cli.exe "Таблицы\Режимы.xlsx" --st --st-single

Оба формата, FBD по группам, ST целиком:
Table2FBD-cli.exe "Таблицы\Режимы.xlsx" --output "Результаты\Режимы" --fbd-step 10 --st-single

--generate ПУТЬ — входная книга; вместо ключа допустим первый аргумент.
--output ПУТЬ, -o ПУТЬ — основа имени результата, с .tple / .fbst или без них.
--name ИМЯ — имя макроса внутри файла; по умолчанию TableParameters.
--sheet ИМЯ — лист; по умолчанию «Данные», если есть, иначе первый.
--fbd — только FBD; --st — только ST. Без этих ключей создаются оба формата.
--fbd-single / --fbd-step ЧИСЛО — единый FBD / группы FBD.
--st-single / --st-step ЧИСЛО — единый ST / группы ST.
--fbd-mode single|grouped, --st-mode single|grouped — явный выбор режима.
--single / --step ЧИСЛО — общий режим обоих форматов для прежних команд.
--help — справка; --version — версия.
По умолчанию оба формата используют группы с шагом 10.

Для одного формата не указывайте одновременно --...-single и --...-step.
--...-mode single допускает заданный шаг: шаг в этом режиме не используется.
Общий --single несовместим с явно заданным шагом.
Относительные пути при прямом запуске EXE отсчитываются от текущей папки.
Пути с пробелами заключайте в кавычки. Выходные папки создаются автоматически.

НАСТРОЙКА GENERATE.BAT
Пример настроек в начале файла:
set "INPUT_FILE=Таблицы\Режимы.xlsx"
set "OUTPUT_FILE=Результаты\Режимы"
set "MACRO_NAME=FanModes"
set "OUTPUT_FORMAT=BOTH"
set "GROUP_STEP=10"
set "SINGLE_MACRO=0"
set "ST_GROUP_STEP=20"
set "ST_SINGLE_MACRO=1"
set "SHEET_NAME="

GROUP_STEP и SINGLE_MACRO относятся только к FBD.
ST_GROUP_STEP и ST_SINGLE_MACRO относятся только к ST.
SINGLE_MACRO=0 — сводный макрос с группами; 1 — всё в один.
OUTPUT_FORMAT: BOTH, FBD или ST. По умолчанию BOTH.
Пустой OUTPUT_FILE: имя входной книги и её папка, расширения по форматам.
Пустой SHEET_NAME: автоматический выбор листа.

Можно перетащить один .xlsx на BAT. Он заменяет INPUT_FILE на время запуска.
Заданные OUTPUT_FILE и настройки групп продолжают действовать.
Допустим вызов Generate.bat "Таблицы\Режимы.xlsx" --st или Generate.bat --fbd.
Ключ --fbd / --st имеет приоритет над OUTPUT_FORMAT.
Несколько входных файлов за один вызов не поддерживаются.

Относительные пути В НАСТРОЙКАХ отсчитываются от папки BAT, включая ..\.
Относительный путь АРГУМЕНТА отсчитывается от текущей папки вызывающего процесса.
Table2FBD-cli.exe должен находиться рядом с BAT.
PAUSE_AT_END=1 — ожидать клавишу после двойного щелчка.
PAUSE_ON_DROP=1 — ожидать клавишу после передачи файла аргументом.
Для автоматического запуска задайте оба значения равными 0.

Сохраняйте BAT в UTF-8 без BOM. Он переключает кодовую страницу и восстанавливает
её перед выходом. Поддерживаются русские пути и пробелы. Сохраняйте кавычки
в командах set. Знак % в буквальном пути настроек запишите как %%.
При вызове из другого BAT используйте call "путь\Generate.bat".
Коды завершения: 0 — успех; 1 — ошибка данных, чтения, записи или генерации;
2 — ошибка параметров. Python-версия также возвращает 130 при Ctrl+C.
Сообщения об успехе идут в stdout, об ошибке — в stderr; кодировка UTF-8.

ПРОВЕРКИ И ОГРАНИЧЕНИЯ
Перед записью проверяются все выбранные форматы. FBD независимо вычисляется
по связям созданной схемы; ST — по созданному тексту CASE. Проверяются все
существующие ID и дополнительные отсутствующие ID, включая границы диапазона.
Ошибка таблицы или генерации не заменяет прежние результаты.
Для записи используются временные файлы.

Проверки на компьютере охватывают 50 записей с шестью REAL и двумя BOOL,
крайние значения UDINT и REAL, независимые режимы и шаги, неизвестные ID,
редактирование, отмену, сохранение Excel, русский язык и относительные пути BAT.
Результаты C++ дополнительно проверены независимыми средствами Python.
Создание ST-блоков проверено классами установленной OwenLogic, включая
сводные блоки, русские имена и крайние значения UDINT / REAL.
Это не проверка компиляции или симуляции полного проекта OwenLogic.
Импорт и работу макросов в OwenLogic проверяет пользователь.
На ПЛК программа не проверялась. Расход памяти и время цикла не измерены.
