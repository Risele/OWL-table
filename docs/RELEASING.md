# Подготовка релиза GitHub

Релиз содержит три ZIP-архива и файл SHA256SUMS.txt:

- `Table2FBD-VERSION-cpp-win32.zip` — готовая C++-программа, консольный EXE,
  BAT, пример таблицы, примеры FBD/ST, справка и лицензии.
- `Table2FBD-VERSION-python-source.zip` — исходники Python, зависимости,
  ресурсы, проверки и скрипт сборки.
- `Table2FBD-VERSION-cpp-source.zip` — исходники C++, встроенные библиотеки,
  ресурсы, скрипт сборки и модули Python для независимой проверки C++.

EXE Python не входит в этот набор. Автоматические архивы Source code,
которые GitHub создаёт для тега, являются дополнительным снимком репозитория.

## Упаковка

Упаковку выполняйте из полной рабочей копии репозитория. Перед новым релизом
согласованно обновите `python/version.py`, строки версии в `cpp/cli.cpp`,
`cpp/window.cpp` и версию в `cpp/app.manifest`.
Соберите C++ по `docs/BUILD.md`, выполните проверки и запустите:

```powershell
python tools/package_release.py
```

По умолчанию результат находится в `release/VERSION/`. Другая папка:

```powershell
python tools/package_release.py --output "D:\Релизы\Table2FBD"
```

Список разрешённых исходных файлов задан в `release_manifest.json`.
При добавлении файлов обновите этот список. Скрипт не сканирует произвольные
папки и не включает локальные проекты, таблицы или результаты отладки.
В готовый C++-архив попадают только явно перечисленные файлы и нейтральные примеры.

## Публикация

Основной README содержит только краткое описание и сведения о запуске.
Работа с BAT описана в `docs/BAT.md`, сборка — в `docs/BUILD.md`.

1. Создайте пустой репозиторий GitHub и отправьте в него подготовленные исходники.
2. В разделе Releases создайте новый релиз и тег `vVERSION` для проверенной версии.
3. Прикрепите все три ZIP-архива и `SHA256SUMS.txt` из `release/VERSION/`.
4. Сохраните черновик, проверьте состав вложений и опубликуйте релиз.

Официальная инструкция GitHub:
https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository

Папки `release/`, `python/dist/`, `cpp/build/`, `cpp/dist/`, `.agents/`,
промежуточные файлы и EXE исключены из Git. В Git хранятся исходники,
а собранные программы и архивы загружаются как вложения релиза.

Имена автора в лицензии и документации не задаются. При создании коммитов Git
использует настроенную пользователем личность; при необходимости используйте
адрес GitHub noreply в локальной настройке репозитория.
